# 词记 · WordLearn

> 面向大学生的英语单词学习应用。手机、电脑通用，**纯本地运行、离线可用、零后端**。
> 它解决的不是「一次背完」，而是**按时复习** —— 每个词按自己的记忆间隔回到你面前，想忘也忘不掉。

| | |
|---|---|
| **技术栈** | React 19 · TypeScript（strict）· Vite 8 · Dexie 4（IndexedDB）· Zustand · lucide-react |
| **形态** | PWA，浏览器打开即用，可加到桌面；无服务端、无网络请求 |
| **数据** | 全部存在浏览器 IndexedDB，支持 JSON 备份导出 / 导入 |
| **词库** | 内置 CET4 核心 653 词 + 雅思学术 30 词；含音标、释义、例句、词形变化、词根词缀、搭配；支持自建词书 |
| **质量** | `tsc` 零错误 · **240 项**自动化测试全通过 · 生产构建通过（JS 197 kB gzip / CSS 6.5 kB gzip） |


## 业务规则

> 完整规则见 [`docs/LOGIC_FLOW.md`](./docs/LOGIC_FLOW.md)。下面是必须知道的几条。

### 三条设计决定（v2 重写的核心）

1. **今日任务是「当日快照」，不是待办清单。**
   `queues` 表按 `[day + kind + bookId]` 存一条记录，包含 `wordIds`（还没结算的词）、`target`（当天任务量）、
   `done`（已完成数）。当天的完成情况由这**一个**快照决定；队列被覆盖也不会丢词 ——
   每个词的到期时间存在 `progress.due` 里，明天自然重新进池。

2. **幂等键是 `(day, kind, bookId)`，不是「列表是否为空」。**
   v1 用「待学习列表为空 → 生成任务」判断，而「空」同时表示「今天还没发过」和「今天发完了」两件事，
   于是在首页和词书之间来回切换就能无限刷词、绕过每日上限。现在生成函数可以被无限次调用，结果始终一致。

3. **当前题目 = 队列的第一个词，没有 `index`。**
   v1 用 `index + consumed + 占位补齐 + 恢复闸门` 四个状态互相配合去实现「回到上次的题」，为它改过五轮。
   现在进度就是 `done / target`，重开 App 天然回到原处，页面层不持有任何进度状态。

### 一次完整的学习循环

```
未学习 ──首次学习（答对 / 错满 3 次强制结算）──▶ learned ──连续答对 7 次（间隔达 90 天）──▶ mastered
                                                  │                                     （毕业，不再进复习池）
                                                  └── 复习答「不认识」→ 连续答对归零，明天重来
```

- **学习队列**：从「未学习列表」随机抽取 `min(每日新词数, 未学习数)` 个 ——
  随机决定抽哪些、按词频决定先学哪个（这两步不是互相抵消）。
- **复习队列**：先按档位比例算数量，再用**到期池**（`due ≤ 今天`）截断；当天新学的词 `due` 是明天，
  因此不会当天就被抽去复习。
- 答错按**单词**计数（不是全局连续计数），作用域是「该词本轮出现在队首期间」；答错**不会提前亮出正确答案**，
  否则用户第一次错就看到绿色选项，「连错 3 次进详情页」这个教学设计就形同虚设。

### 复习抽样档位

| 已学习单词总数 | 抽取比例 |
|---|---|
| ≤ 10 | 100% |
| > 10 且 ≤ 60 | 80% |
| > 60 且 ≤ 150 | 60% |
| **> 150** | **50%（兜底档）** |

再取 `min(档位数量, 每日复习上限, 到期池大小)`；每日上限设为 0 表示今天不复习。

### 间隔表（答「认识」后往后推）

连续答对 `0~7` 次 → `1 / 2 / 4 / 7 / 15 / 30 / 60 / 90` 天；达到 90 天标记为 `mastered`（毕业）。
答「不认识」则归零到 1 天。

### 保证「今天一定能结束」

同一个词当天最多出现 **3 轮**（`MAX_ROUNDS_PER_DAY`）：学习侧第 3 次错满 3 个选项、复习侧第 3 次点
「不认识」，都会**强制结算**（记为已学 / 已复习，`lapses + 1`，明天优先出现）。
没有这个上限，用户一直点「不认识」就永远结束不了 —— 这是 v1 的死循环。

### 进度与完成度

| 指标 | 公式 | 约束 |
|---|---|---|
| 今日进度 | `done / target` | 分子是单调计数器、分母是生成时冻结的快照，显示时 clamp |
| 单本词书完成度 | `已学习数 / 词书总词数` | 含已毕业词，clamp 到 0~1 |
| 全部词书完成度 | `全局已学习数 / 全部词书去重后总词数` | 分母去重，避免共有词被重复计数 |

## 技术架构

### 数据表（IndexedDB，9 张）

| 表 | 主键 | 说明 |
|---|---|---|
| `books` | `id` | 词书 |
| `words` | `id`（小写单词） | 词条内容，只读 |
| `bookWords` | `[bookId + wordId]` | 词书单词表 —— **联合主键天然去重** |
| `progress` | `wordId` | 学习进度（状态 / 到期日 / 间隔 / 连续答对 / 遗忘次数）—— **同一单词全局只学一次** |
| `queues` | `[day + kind + bookId]` | 当日任务快照 —— **联合主键天然幂等** |
| `daily` | `day` | 当日聚合统计 |
| `logs` | `++id` | 作答流水（完成页的真实用时 / 正确率据此计算） |
| `settings` | `id` | 全局设置（单行） |
| `runState` | `id` | 每日任务幂等键、提醒去重 |

**四个「列表」都不是表**：未学习列表 = 词书单词表 − 已学习；已学习列表 = 词书单词表 ∩ progress；
待学习 / 待复习 = 当天队列。这样不存在「从待学习移除后忘了加进已学习」这类多表同步 bug。

### 数据流

```
用户操作
  └─▶ 页面调用 lib/tasks.ensureDailyTask（幂等）或 lib/session.commitXxx（单事务）
        └─▶ Dexie 事务：queues + progress + daily + logs 一次写完
              └─▶ liveQuery 推送新值 → useQuery → React 重新渲染
```

页面**不持有业务状态**：所有真相都在数据库，UI 只负责订阅渲染。
提交一律「先落盘、后跳转」，并带 `busy` 锁防连点。

## 开发约定

1. **UI 只用 `src/styles.css` 里已有的类和 `src/components/ui.tsx` 里的组件**，不新增样式文件 ——
   全站圆角、间距、配色、触控尺寸才能保持一致。完整清单见 [`docs/UI_CONTRACT.md`](./docs/UI_CONTRACT.md)。
2. **`useQuery` 的依赖数组只能放原始值**（字符串 / 数字 / 布尔）。放对象会因为每次发射都是新引用而无限重订阅。
3. **队列的「读—改—写」必须在同一个事务内**；队列与进度必须在同一次写入里落盘。
4. **出队一律按 `wordId` 定位**，绝不按位置（`slice(0,1)` 会删错词）。
5. **所有「今天」都从 `useApp((s) => s.today)` 取**，不要自己 `new Date()`，否则跨天不会刷新。
6. 改每日新词数 / 复习上限 / 当前词书，一律走 `patchSettings` —— 它会重建今天「还没开始」的队列；
   已经开始的队列保持冻结（进度不能倒退）。
7. 纯图标按钮必须用 `<IconButton icon={X} label="说明" />`；触控目标 ≥44px；状态不能只用颜色表达。
8. **凡是「点进去还能返回」的跳转，一律用 `useGo()`；子页面的返回按钮一律用 `useGoBack(fallback)`。**
   裸 `navigate()` 不会记录来源，返回时只能落到写死的兜底页 ——「从首页进词书管理，返回却到了我的」
   这个 bug 已经因为同样的原因出现过两次。`tests/ui.test.tsx` 里有 7 组「入口 → 子页面 → 返回」回归测试盯着它。

## 测试

```bash
npm test              # 全部（240 项）
npm run test:logic    # 54 项：日期工具、抽样档位、间隔表、干扰项
npm run test:db       # 124 项：队列幂等、作答提交、跨天、并发、完整性自检、备份恢复
npm run test:ui       # 62 项：真实 React 应用端到端（jsdom + fake-indexeddb）
```

测试运行器 `scripts/test-runner.mjs` 用 esbuild 把源码转译成 ESM 后交给 Node 原生解析依赖
（**不打包 npm 包**）—— 这是必须的：Dexie 会在模块加载那一刻读取 `globalThis.indexedDB`，
一旦打包出两份副本，`liveQuery` 会静默失效，表现为「查询明明有数据，页面永远是空的」。

**写测试会踩到的两个坑**（已在 `tests/env.ts` 中处理）：

- `settle()` 必须**先在 `act` 之外等待、再用一次空 `act` 冲刷**。在 `act(async () => sleep(3000))` 里，
  Dexie 的 `liveQuery` 首个查询根本不会启动；而它发射的更新又发生在 `act` 之外，需要一次 act 边界才会渲染进 DOM。
- 刚跳转过去的页面往往还有一次 React 提交，**「先取元素、再点击」会点到已被替换掉的旧节点上**，点击静默落空。
  凡是要点刚渲染出来的按钮，都走 `tap()`（等一帧 → 重新查询 → 点击）。

## 无障碍与交互

- 触控目标 ≥44px；正文对比度 ≥4.5:1；`:focus-visible` 有可见焦点环。
- 进度条 `role="progressbar"` + `aria-valuenow`；提示 `role="status" aria-live="polite"`；
  纯图标按钮都有 `aria-label`；选项对错同时用图标和文字表达，不只靠颜色。
- 尊重 `prefers-reduced-motion`；`prefers-color-scheme` 决定首屏深浅色，避免夜间打开闪白。
- 视图缩放未被禁用（WCAG 1.4.4）。
- 响应式：手机底部 4 个标签栏；≥900px 换成左侧竖栏导航 + 内容居中限宽。

## 已知限制

- **每日提醒只在应用打开时生效**：纯本地应用没有推送能力，到点后若任务没做完会给一条应用内提示，
  用 `lastRemindedDay` 保证一天只提醒一次。
- **发音依赖系统语音包**：环境不支持时按钮置灰并说明原因，不会静默失败。
- **换设备需要手动备份**：没有云端账号，用「我的 → 数据管理 → 导出 / 导入 JSON」迁移。
- **单词本列表是渲染层分批**（每批 30 条），数据层仍一次性读入当前词书的词 ——
  词书规模上到几万词时需要换成游标分页。
- **像素级视觉未在真实浏览器中验证过**：开发环境没有可用浏览器，交互与结构由 jsdom 端到端测试保证。

## 关于 npm 缓存

开发沙箱里的 `.npmrc` 把 npm 缓存指向工作区内的 `.npm-cache/`。这不是洁癖：该环境的 `~/.npm`
不可写，不这样配置 `npm install` 会直接以 EACCES 失败。它里面是本机绝对路径，所以**没有纳入版本控制**
（`.gitignore` 已忽略）—— 在你自己机器上装依赖不需要它。

以下目录同样已忽略：`.npm-cache/`、`.npm-logs/`、`node_modules/`、`dist/`、`.tmp/`。
